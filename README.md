# 🌙 مُعبِّر الأحلام — Dreams Interpreter

تطبيق ويب لتفسير الأحلام اعتماداً على **مراجع تفسير الأحلام الإسلامية** (ابن سيرين،
النابلسي). كل حلم محادثة مستقلة تُحفظ بتاريخها، مع لوحة متابعة وملخص عام، وإمكانية
**الإدخال بالصوت**.

## المميزات

- 🔐 **تسجيل/دخول** بحسابات (JWT في httpOnly cookie + bcrypt).
- 💬 **شات تفسير الأحلام** — كل حلم = conversation له سياقه، مؤصّل عبر **RAG** على
  قاعدة معرفة من **+5600 مقتطف** من ثلاثة معاجم كلاسيكية (ابن سيرين، وتعطير الأنام
  للنابلسي، والإشارات لابن شاهين)، تُسترجَع أقرب الرموز وتُحقَن في سياق الـ AI لمنع التأليف.
- 📅 **تتبّع بالتواريخ + تقويم** — احفظ كل حلم وتاريخه (حتى لو حلم قديم تتذكره)،
  واستعرض أحلامك على **تقويم شهري** (`/calendar`) مع مؤشّر مزاج لكل يوم.
- 📌 **خلاصة الحلم** — بضغطة زر، يُلخَّص الشات كله في بطاقة: *الحلم الكامل + التفسير
  النهائي*، تُحفظ وتظهر في الـ dashboard والتقويم لقراءة سريعة.
- 🔗 **استشهاد موثّق** — المقتطفات تُعطى للموديل مرقّمة، ويُلزَم بذكر رقم ما استند إليه،
  فيُبنى تذييل المصادر من الأرقام التي ذكرها فعلاً — برابط **لكل رمز** ونسبة كل قول لكتابه.
- 👍 **تقييم التفسير** — زرّا «ظبط / ما ظبطش» أسفل كل تفسير، تتجمّع منهما بيانات جودة
  حقيقية في لوحة الأدمن (نسبة الرضا، أسباب الرفض، الرموز المتكررة في التفاسير المرفوضة).
- 📊 **Dashboard + ملخص عام** — إجمالي الأحلام، أكثر الرموز تكراراً، مزاج الأحلام،
  ونظرة عامة تحليلية.
- 🎤 **إدخال بالصوت** عبر Web Speech API (مجاني، عربي مدعوم).
- ⚡ **ردّ متدفّق (streaming)** يظهر أول بأول أثناء التفسير.
- 🔍 **بحث وفلترة** (نص/مزاج/نوع الرؤيا) + **إحصاءات** (charts: الأحلام عبر الأشهر،
  توزيع المزاج، أكثر الرموز).
- 🧭 **تصنيف الرؤيا** (رؤيا / أضغاث / حديث نفس) مع مراعاة آداب الرؤيا.
- 🗑 **سلة مهملات** (حذف ناعم/استرجاع) و**مشاركة عامة** للقراءة فقط و**تصدير JSON**
  و**طباعة/PDF**.
- 🎨 **ثيم نهاري/ليلي**، 🔒 **قفل PIN** للجهاز، و🌅 **تذكير يومي** بالتدوين.

## التقنيات

- **Next.js 15** (App Router) — full-stack، بيتنشر على Vercel.
- **libSQL / Turso** — قاعدة بيانات SQLite سحابية تشتغل serverless (مجانية).
- **Drizzle ORM** — يسهّل التبديل لـ Postgres لاحقاً لو لزم.
- **مزود AI متوافق مع OpenAI (agnostic)** — OpenAI / Groq / OpenRouter / محلي…
- **Tailwind CSS** — واجهة عربية RTL بمظهر ليلي.

## التشغيل محلياً

```bash
npm install
cp .env.example .env        # واضبط القيم
npm run dev                 # http://localhost:3000
```

> بدون مفتاح `AI_API_KEY` التطبيق يعمل بوضع **fallback** يفسّر من قاعدة الرموز
> المحلية مباشرة (بدون استدعاء خارجي). اضبط المفتاح لتفسير تفاعلي أعمق.

قاعدة البيانات تُنشأ **تلقائياً** عند أول طلب (`CREATE TABLE IF NOT EXISTS`)،
فلا حاجة لخطوة migration منفصلة.

## المتغيّرات البيئية

| المتغيّر | الوصف |
|----------|-------|
| `DATABASE_URL` | `file:local.db` محلياً، أو `libsql://...turso.io` للإنتاج |
| `DATABASE_AUTH_TOKEN` | توكن Turso (للإنتاج فقط) |
| `AUTH_SECRET` | سرّ طويل عشوائي لتوقيع الجلسات (`openssl rand -base64 48`) |
| `AI_API_KEY` | مفتاح المزود (اختياري — بدونه يعمل fallback) |
| `AI_BASE_URL` | عنوان المزود المتوافق مع OpenAI |
| `AI_MODEL` | اسم الموديل |

## النشر على Vercel (مجاناً)

1. أنشئ قاعدة Turso مجانية من [turso.tech](https://turso.tech) واحصل على
   `DATABASE_URL` + `DATABASE_AUTH_TOKEN`.
2. اربط الريبو بـ Vercel، وأضِف المتغيّرات البيئية أعلاه.
3. Deploy — والـ schema يُنشأ تلقائياً عند أول طلب.

## البنية

```
src/
  app/                # صفحات + API routes (App Router)
    api/auth/         # register / login / logout / me
    api/dreams/       # CRUD + الرسائل
    api/summary/      # الملخص العام
  components/         # واجهة العميل (شات، لوحة، إدخال صوتي)
  db/                 # schema + client + إنشاء الجداول
  lib/                # auth, ai, rag (استرجاع), arabic (تطبيع), خدمة الأحلام
  data/               # dream-symbols.json (رموز + مشاعر) + knowledge-base.json (كوربوس RAG)
scripts/
  build-corpus.py     # بناء الكوربوس من المعاجم الثلاثة (قابل لإعادة التشغيل)
```

## قاعدة المعرفة والـ RAG

- `src/data/knowledge-base.json` يحتوي **+5600 مقتطف** من ثلاثة معاجم تراثية:
  *تفسير الأحلام لابن سيرين*، و*تعطير الأنام* للنابلسي، و*الإشارات في علم العبارات*
  لابن شاهين — مُجمَّعة عبر `scripts/build-corpus.py` (النصوص تراث عام).
  **1907 رمزاً** له أكثر من قول، فيرى المفسّر أكثر من وجه ويوازن بينها.
- لكل مقتطف **رابط للرمز نفسه** (مرساة داخل صفحة الحرف، أو صفحة الرمز المستقلة)
  لا لصفحة الحرف كاملة: **3577 رابطاً مميّزاً**.
- عند تفسير حلم، يقوم `src/lib/rag.ts` باسترجاع الرموز عبر مطابقة اسم الرمز فقط
  (المطابقات اللفظية الضعيفة لا تصل للموديل إطلاقاً، لأنها أكبر مصدر للتأليف)،
  ثم يوازن `buildGrounding` بين اتساع التغطية (رمزان لكل كتاب أولاً) وعمقها.
- الاسترجاع **محلي بالكامل** (بلا استدعاءات خارجية وقت الطلب)، فيعمل حتى في وضع
  الـ fallback بدون مفتاح AI.

### استرجاع هجين (lexical + دلالي)

الاسترجاع **هجين**: مطابقة اسم الرمز اللفظية (دقيقة) + جيران دلاليون بالـ
embeddings (يمسكون المرادفات التي يفوتها اللفظ، مثل «أعوم في مياه» ← ماء/بحر).

المتجهات مبنية مسبقاً ومضغوطة (int8) في `src/data/kb-vectors.json` (~6MB).
لإعادة بنائها بموديل embedding متوافق مع OpenAI:

```bash
AI_API_KEY=... AI_BASE_URL=https://openrouter.ai/api/v1 \
AI_EMBED_MODEL="nvidia/llama-nemotron-embed-vl-1b-v2:free" \
node scripts/build-embeddings.mjs        # ينشئ embeddings.json الخام
node scripts/quantize-embeddings.mjs     # يضغطه إلى kb-vectors.json (int8)
```

يُفعَّل الجزء الدلالي تلقائياً عند ضبط `AI_EMBED_MODEL` ووجود `kb-vectors.json`؛
وإلا يبقى الاسترجاع لفظياً بالكامل (مجاني، محلي، بلا زمن انتظار). منطق التشابه
(cosine) في `src/lib/vectors.ts` ومُغطّى باختبارات.

> ملاحظة خصوصية: تفعيل الـ embedding يرسل نص الحلم إلى مزوّد الـ embeddings.
> الموديلات المجانية على OpenRouter قد تتطلب السماح باستخدام البيانات في التدريب.
